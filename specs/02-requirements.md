# 需求规格说明书（Requirements Specification）

## 1. 项目目标

构建一个图书管理系统，支持读者注册与借阅证管理、馆藏与书目维护、图书管理员代理借还、借阅查询、网络预约、超期罚款与规则维护；
系统采用分层架构 + MVC，并以 Agent 辅助、人工审查的方式完成规格与实现。

## 2. 参与者

| 编号 | 参与者 | 说明 |
|---|---|---|
| A-01 | Reader（读者） | 系统注册用户，可查询图书、查询本人借阅信息、预约/取消预约 |
| A-02 | StudentReader（学生读者） | 读者的子类，含专科生/本科生/研究生/博士生，按类型适用不同借阅规则 |
| A-03 | TeacherReader（教师读者） | 读者的子类，适用教师借阅规则 |
| A-04 | Librarian（图书管理员） | 代理读者办理借书、还书，查询读者借阅信息 |
| A-05 | SystemAdmin（系统管理员） | 办理/删除借阅证，维护管理员、图书标题、馆藏副本、借阅与罚款规则 |

## 3. 功能需求

### FR-001 注册读者账号

读者提交姓名、证件号、联系方式、读者类型、院系或单位，系统创建读者账号，状态为 `ACTIVE`。

- 验收标准：
  1. 必填项缺失时拒绝创建并返回字段级错误。
  2. 同一证件号重复注册被拒绝。
  3. 创建成功后可通过 ID 查询到该读者且类型为指定读者类型。

### FR-002 办理借阅证

系统管理员为已注册读者办理借阅证，生成借阅证号（`CARD+年份+6位序号`），记录读者姓名、院系或单位、借阅证号。

- 验收标准：
  1. 读者不存在时办理失败。
  2. 读者已持有有效借阅证时办理失败。
  3. 生成的借阅证号全局唯一且符合格式。

### FR-003 删除借阅证

系统管理员注销借阅证。

- 验收标准：
  1. 存在未还借阅记录时拒绝注销。
  2. 注销后借阅证状态为 `REVOKED`，不可用于借书。
  3. 历史借阅记录仍可查询。

### FR-004 添加图书管理员

系统管理员创建图书管理员账号（工号、姓名）。

- 验收标准：工号唯一；创建后该账号可执行借书、还书。

### FR-005 删除图书管理员

系统管理员停用/删除图书管理员账号。

- 验收标准：删除后该工号不能执行借还操作，返回权限错误。

### FR-006 添加图书标题信息

系统管理员添加题名（书名、作者、ISBN、出版社、出版年、借出物类型）。

- 验收标准：ISBN 非空；同一 ISBN 重复添加被拒绝；添加后可按题名检索。

### FR-007 删除图书标题信息

系统管理员删除题名。

- 验收标准：题名下存在在借副本时拒绝删除；删除后检索不到该题名。

### FR-008 添加馆藏副本

系统管理员为题名添加馆藏副本，系统生成唯一条码（`ITEM+年份+6位序号`），初始状态 `AVAILABLE`。

- 验收标准：条码全局唯一；题名不存在时添加失败。

### FR-009 删除馆藏副本

系统管理员删除或下架副本。

- 验收标准：副本处于 `ON_LOAN` 时拒绝删除；删除后不可被检索与借阅。

### FR-010 查询图书

读者与管理员按题名、作者、ISBN 查询图书，返回题名信息及各副本可借状态。

- 验收标准：支持模糊匹配题名；结果包含可借副本数量。

### FR-011 借阅图书

图书管理员输入借阅证号与副本条码办理借书。系统依次校验：
借阅证有效性 → 未缴罚款 → 超期未还 → 借阅数量上限 → 副本可借与预约占用，
通过后创建借阅记录，计算应还日期，更新副本状态为 `ON_LOAN`。

- 验收标准：
  1. 借阅证无效/已注销时拒绝并返回 `CARD_INVALID`。
  2. 超过该读者类型最大借阅数量时拒绝并返回 `QUOTA_EXCEEDED`。
  3. 存在超期未还记录时拒绝并返回 `READER_HAS_OVERDUE_LOAN`。
  4. 存在未缴罚款时拒绝并返回 `READER_HAS_UNPAID_FINE`。
  5. 副本不可借或被他人预约时拒绝并返回 `ITEM_NOT_AVAILABLE` / `ITEM_RESERVED_BY_OTHER`。
  6. 借书成功后生成 Loan 记录，应还日期 = 借出日期 + 该读者类型借阅期限。

### FR-012 归还图书

图书管理员输入副本条码办理还书。系统验证图书是否为本馆藏书且处于借出状态，
关闭借阅记录，副本状态置为 `AVAILABLE`；若超期则按对应借出物类型罚款规则生成罚款记录。

- 验收标准：
  1. 非本馆藏书或非在借副本时拒绝并返回 `ITEM_NOT_ON_LOAN`。
  2. 归还成功后借阅记录状态为 `RETURNED`，副本状态为 `AVAILABLE`。
  3. 超期归还按规则生成 `FineRecord`，金额 = 超期天数 × 每日金额（扣免罚期、受上限约束）。

### FR-013 查询借阅信息

读者查询本人借阅记录；图书管理员按借阅证号查询指定读者借阅记录。

- 验收标准：返回借出日期、应还日期、归还日期、状态、是否超期；读者只能查询本人数据。

### FR-014 预约图书

读者对题名发起预约，系统按创建时间排队，生成排队序号。

- 验收标准：
  1. 同一读者对同一题名不可重复预约。
  2. 单人有效预约数超过 3 条时拒绝。
  3. 排队序号按创建时间递增。
  4. 读者可取消本人预约，取消后该预约标记 `CANCELLED`。
  5. 有有效预约的题名，仅队首读者可借。

### FR-015 计算超期罚款

系统根据借出物类型的 `FineRule` 计算超期罚款。

- 验收标准：
  1. 未超期或在免罚期内罚款为 0。
  2. 罚款金额受单笔上限约束。
  3. 罚款记录状态可为 `UNPAID` / `PAID`，未缴罚款阻止借书。

### FR-016 维护借阅规则和罚款规则

系统管理员维护各读者类型的借阅数量、借阅期限，以及各借出物类型的免罚期、每日罚款、罚款上限。

- 验收标准：规则变更后立即对新的借书/还书生效；非法值（负数、空值）被拒绝。

## 4. 非功能需求

| 编号 | 类别 | 需求 |
|---|---|---|
| NFR-001 | 可维护性 | 四层分层架构 + MVC，禁止跨层反向依赖 |
| NFR-002 | 可测试性 | 核心用例自动化测试覆盖率 ≥ 80%，领域层可脱离框架单测 |
| NFR-003 | 安全性 | 三类角色权限隔离，越权必须显式失败 |
| NFR-004 | 可靠性 | 借书/还书在同一事务内完成，状态更新要么全成功要么全回滚 |
| NFR-005 | 性能 | 单馆 10 万副本规模下，题名检索响应时间 < 1s |
| NFR-006 | 可移植性 | 领域层不依赖具体数据库实现 |
| NFR-007 | 可审计性 | 所有 Agent 生成内容记录于 `19-ai-usage-log.md` |

## 5. 业务规则

| 编号 | 规则 |
|---|---|
| BR-001 | 一个读者最多持有一张有效借阅证 |
| BR-002 | 借阅证处于 `REVOKED` / `LOST` 状态时不可借书 |
| BR-003 | 借阅数量统计口径为状态 `BORROWED` 或 `OVERDUE` 的未还记录 |
| BR-004 | 存在超期未还图书的读者禁止借书 |
| BR-005 | 存在未缴罚款的读者禁止借书 |
| BR-006 | 只有状态为 `AVAILABLE` 的副本可借；论文类（`loanable=false`）不可外借 |
| BR-007 | 应还日期 = 借出日期 + 读者类型对应借阅期限 |
| BR-008 | 超期天数 = 实际归还日期 − 应还日期 − 免罚期，结果为负记 0 |
| BR-009 | 罚款 = 超期天数 × 每日金额，不超过该借出物类型的单笔上限 |
| BR-010 | 预约按创建时间排队；预约保留 7 天，超时自动 `EXPIRED` |
| BR-011 | 存在有效预约的题名仅允许队首读者借阅 |
| BR-012 | 单人同时有效预约数量上限为 3 |
| BR-013 | 借书与还书必须由图书管理员代理执行 |
| BR-014 | 借阅证、管理员、书目、副本、规则的维护只能由系统管理员执行 |
| BR-015 | 读者只能查询与操作本人借阅、预约数据 |

## 6. 数据需求（概述）

需持久化的核心对象：读者、借阅证、图书管理员、系统管理员、图书标题、馆藏副本、借阅记录、预约记录、借阅规则、罚款规则、罚款记录。
详见 `13-database-design.md`。

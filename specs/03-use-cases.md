# 用例文本规格（Use Case Specifications）

## 0. 参与者

| 参与者 | 说明 |
|---|---|
| Reader | 读者（抽象） |
| StudentReader | 学生读者，泛化自 Reader（专科生/本科生/研究生/博士生） |
| TeacherReader | 教师读者，泛化自 Reader |
| Librarian | 图书管理员，代理读者办理借还 |
| SystemAdmin | 系统管理员，负责系统维护 |

---

## UC-001 注册读者账号

- 主要参与者：Reader（读者本人）
- 次要参与者：无
- 前置条件：无
- 后置条件：系统存在一条 `ACTIVE` 状态的读者记录
- 基本事件流：
  1. 读者提交姓名、证件号、联系方式、读者类型、院系或单位。
  2. 系统校验必填项与证件号唯一性。
  3. 系统创建读者账号并生成读者 ID。
  4. 系统返回注册结果与读者 ID。
- 备选事件流：
  3a. 证件号已存在：系统提示重复注册并终止。
- 异常事件流：
  2a. 必填项缺失或格式非法：系统返回字段级校验错误。
- 关联需求：FR-001

## UC-002 查询图书

- 主要参与者：Reader
- 次要参与者：Librarian
- 前置条件：无（读者可选登录后查询）
- 后置条件：无状态变更
- 基本事件流：
  1. 用户输入题名/作者/ISBN 关键字。
  2. 系统检索图书标题信息。
  3. 系统返回匹配的题名列表及各副本可借状态、可借数量。
- 备选事件流：
  3a. 无匹配结果：系统返回空列表并提示。
- 异常事件流：
  2a. 检索服务不可用：系统返回系统错误。
- 关联需求：FR-010

## UC-003 查询借阅信息

- 主要参与者：Reader
- 次要参与者：Librarian（代读者查询）
- 前置条件：读者已注册
- 后置条件：无状态变更
- 基本事件流：
  1. 读者提交本人读者 ID。
  2. 系统校验身份，仅允许查询本人数据。
  3. 系统返回借阅记录列表（借出日期、应还日期、归还日期、状态、是否超期）。
- 备选事件流：
  1a. 图书管理员代查：管理员提交借阅证号，系统校验管理员权限后返回该读者借阅记录。
- 异常事件流：
  2a. 读者查询他人数据：系统拒绝并返回权限错误。
- 关联需求：FR-013

## UC-004 预约图书

- 主要参与者：Reader
- 次要参与者：Librarian（处理到书借阅）
- 前置条件：读者已注册；题名存在
- 后置条件：生成一条 `WAITING` 状态的预约记录并分配排队序号
- 基本事件流：
  1. 读者选择题名发起预约。
  2. 系统校验题名存在且可预约。
  3. 系统校验该读者对同一题名无重复有效预约。
  4. 系统校验该读者有效预约数未超过 3 条。
  5. 系统按创建时间生成排队序号，创建预约记录。
  6. 系统返回预约结果与排队序号。
- 备选事件流：
  5a. 题名存在可借副本：系统仍按排队规则登记，并标记可借通知状态。
- 异常事件流：
  3a. 重复预约：返回 `DUPLICATE_RESERVATION`。
  4a. 超过预约上限：返回 `RESERVATION_LIMIT_EXCEEDED`。
- 关联需求：FR-014

## UC-005 取消预约

- 主要参与者：Reader
- 前置条件：存在本人有效预约
- 后置条件：预约记录状态置为 `CANCELLED`
- 基本事件流：
  1. 读者选择本人预约记录申请取消。
  2. 系统校验预约归属。
  3. 系统将预约状态置为 `CANCELLED`。
- 异常事件流：
  2a. 取消他人预约：系统拒绝并返回权限错误。
- 关联需求：FR-014

## UC-101 办理借书

- 主要参与者：Librarian
- 次要参与者：Reader
- 前置条件：图书管理员账号有效；读者持有有效借阅证
- 后置条件：生成一条 `BORROWED` 借阅记录；对应副本状态为 `ON_LOAN`
- 基本事件流：
  1. 图书管理员输入借阅证号。
  2. 系统验证借阅证是否存在且有效（BR-002）。
  3. 系统检查读者是否存在未缴罚款（BR-005）。
  4. 系统检查读者是否存在超期未归还图书（BR-004）。
  5. 系统检查读者当前在借数量是否超过该读者类型上限（BR-003）。
  6. 系统显示读者信息（姓名、类型、在借数量、可借额度）。
  7. 图书管理员输入图书副本条码。
  8. 系统验证图书是否为本馆藏书且状态为 `AVAILABLE`，并检查是否存在他人优先预约（BR-006、BR-011）。
  9. 系统按读者类型借阅期限计算应还日期，创建借阅记录。
  10. 系统更新副本状态为 `ON_LOAN`，读者在借数量加一。
  11. 系统返回借书成功与应还日期。
- 备选事件流：
  8a. 若借阅人正是该题名队首预约者：系统允许借出并同时将该预约置为 `FULFILLED`。
- 异常事件流：
  2a. 借阅证不存在或已注销：返回 `CARD_INVALID`，终止。
  3a. 存在未缴罚款：返回 `READER_HAS_UNPAID_FINE`，终止。
  4a. 存在超期未还：返回 `READER_HAS_OVERDUE_LOAN` 并列出超期清单，终止。
  5a. 超过借阅数量上限：返回 `QUOTA_EXCEEDED`，终止。
  8b. 副本不可借：返回 `ITEM_NOT_AVAILABLE`，终止。
  8c. 副本被他人预约保留：返回 `ITEM_RESERVED_BY_OTHER`，终止。
  8d. 论文类不可外借：返回 `ITEM_NOT_LOANABLE`，终止。
- 关联需求：FR-011、BR-003~BR-007、BR-011、BR-013

## UC-102 办理还书

- 主要参与者：Librarian
- 次要参与者：Reader
- 前置条件：该副本处于借出状态
- 后置条件：借阅记录状态为 `RETURNED`；副本状态恢复 `AVAILABLE`；如超期则生成罚款记录
- 基本事件流：
  1. 图书管理员输入副本条码。
  2. 系统验证图书是否为本馆藏书（条码存在）。
  3. 系统查找该副本处于 `BORROWED` / `OVERDUE` 的借阅记录。
  4. 系统登记归还日期，判断应还日期与实际归还日期是否存在超期。
  5. 如超期，系统按借出物类型的罚款规则计算罚款金额（BR-008、BR-009），生成罚款记录。
  6. 系统将该借阅记录状态置为 `RETURNED`。
  7. 系统将副本状态置为 `AVAILABLE`，读者在借数量减一。
  8. 系统返回还书结果与罚款信息。
- 备选事件流：
  5a. 超期天数在免罚期内：罚款金额为 0，不生成罚款记录。
  7a. 若该题名存在排队预约：系统将副本状态置为 `RESERVED` 并通知队首读者，保留 7 天（BR-010）。
- 异常事件流：
  2a. 非本馆藏书：返回 `ITEM_NOT_FOUND`，终止。
  3a. 副本未在借：返回 `ITEM_NOT_ON_LOAN`，终止。
- 关联需求：FR-012、FR-015、BR-008~BR-010、BR-013

## UC-103 查询读者借阅信息（管理员视角）

- 主要参与者：Librarian
- 前置条件：管理员账号有效
- 后置条件：无状态变更
- 基本事件流：
  1. 管理员输入借阅证号。
  2. 系统校验借阅证有效性。
  3. 系统返回该读者在借、历史、超期与罚款信息。
- 异常事件流：
  1a. 借阅证无效：返回 `CARD_INVALID`。
- 关联需求：FR-013

## UC-201 办理借阅证

- 主要参与者：SystemAdmin
- 次要参与者：Reader
- 前置条件：读者账号已注册
- 后置条件：生成一张有效借阅证
- 基本事件流：
  1. 系统管理员输入读者 ID。
  2. 系统校验读者存在且状态正常。
  3. 系统校验该读者未持有有效借阅证（BR-001）。
  4. 系统生成借阅证号（`CARD+年份+6位序号`），记录读者姓名、院系或单位、借阅证号、发放日期。
  5. 系统返回借阅证信息。
- 异常事件流：
  2a. 读者不存在：返回 `READER_NOT_FOUND`。
  3a. 已持有有效借阅证：返回 `CARD_ALREADY_EXISTS`。
- 关联需求：FR-002、BR-001

## UC-202 删除借阅证

- 主要参与者：SystemAdmin
- 前置条件：借阅证存在
- 后置条件：借阅证状态为 `REVOKED`
- 基本事件流：
  1. 系统管理员输入借阅证号。
  2. 系统校验借阅证存在。
  3. 系统检查该证名下是否存在未还借阅记录。
  4. 系统将借阅证状态置为 `REVOKED`。
- 异常事件流：
  3a. 存在未还记录：返回 `CARD_HAS_ACTIVE_LOANS`，终止。
- 关联需求：FR-003

## UC-203 添加图书管理员

- 主要参与者：SystemAdmin
- 前置条件：操作人为系统管理员
- 后置条件：生成图书管理员账号
- 基本事件流：
  1. 系统管理员输入工号、姓名。
  2. 系统校验工号唯一性。
  3. 系统创建管理员账号并置为启用。
- 异常事件流：
  1a. 操作人非系统管理员：返回 `PERMISSION_DENIED`。
  2a. 工号重复：返回 `LIBRARIAN_ALREADY_EXISTS`。
- 关联需求：FR-004

- 主要参与者：SystemAdmin
- 前置条件：管理员账号存在
- 后置条件：账号置为停用，不可办理借还
- 基本事件流：
  1. 系统管理员输入工号。

- 异常事件流：
  1a. 非系统管理员操作：返回 `PERMISSION_DENIED`。
  2a. 账号不存在：返回 `LIBRARIAN_NOT_FOUND`。
- 关联需求：FR-005

## UC-206 删除图书标题信息

- 主要参与者：SystemAdmin
- 前置条件：题名存在
- 后置条件：题名记录被删除或标记下架
- 基本事件流：
  1. 系统管理员选择题名执行删除。
  2. 系统检查题名下是否存在在借副本。

## UC-207 添加馆藏副本

- 主要参与者：SystemAdmin
- 前置条件：题名已存在
- 后置条件：生成一条馆藏副本记录，状态 `AVAILABLE`
- 基本事件流：
  1. 系统管理员选择题名并录入馆藏地。
  2. 系统生成唯一条码（`ITEM+年份+6位序号`）。
  3. 系统创建副本记录，初始状态 `AVAILABLE`。
- 异常事件流：
  1a. 题名不存在：返回 `TITLE_NOT_FOUND`。
  1b. 非系统管理员操作：返回 `PERMISSION_DENIED`。
- 关联需求：FR-008

## UC-208 删除馆藏副本

- 主要参与者：SystemAdmin
- 前置条件：副本存在且未在借
- 后置条件：副本被删除或标记为 `WITHDRAWN`
- 基本事件流：
  1. 系统管理员输入副本条码。
  2. 系统校验副本存在且状态非 `ON_LOAN`。
  3. 系统删除副本或标记为 `WITHDRAWN`。
- 异常事件流：
  2a. 副本在借：返回 `ITEM_ON_LOAN_CANNOT_DELETE`，终止。
- 关联需求：FR-009

## UC-209 维护借阅规则和罚款规则

- 主要参与者：SystemAdmin
- 前置条件：操作人为系统管理员
- 后置条件：规则被更新并对后续业务生效
- 基本事件流：
  1. 系统管理员选择读者类型或借出物类型。
  2. 系统管理员提交借阅数量、借阅期限或免罚期、每日罚款、罚款上限。
  3. 系统校验数值合法性（非负、非空）。
  4. 系统保存规则。
- 异常事件流：
  1a. 非系统管理员操作：返回 `PERMISSION_DENIED`。
  3a. 数值非法：返回 `INVALID_POLICY_VALUE`。
- 关联需求：FR-016

## UC-210 计算超期罚款

- 主要参与者：SystemAdmin / 系统（由 UC-102 包含调用）
- 前置条件：存在已超期的借阅记录
- 后置条件：生成罚款记录（金额可为 0）
- 基本事件流：
  1. 系统获取借阅记录对应的借出物类型。
  2. 系统加载该类型的罚款规则（免罚期、每日金额、上限）。
  3. 系统计算超期天数 = 实际归还日期 − 应还日期 − 免罚期。
  4. 系统计算罚款 = 超期天数 × 每日金额，并受上限约束。
  5. 系统生成罚款记录，状态 `UNPAID`。
- 异常事件流：
  2a. 未找到对应罚款规则：使用默认规则并记录告警。
- 关联需求：FR-015、BR-008、BR-009
